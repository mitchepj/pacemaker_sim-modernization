## Part B — Additional deviations discovered and resolved during translation (not among the 6 named findings)

These were found by direct code-reading during translation, not guessed, and none of them change legacy's OBSERVABLE runtime behavior (each is accompanied by the trace/proof that makes it safe):

- **#9 — Removed `g_egm_hist[]` / `sensing_push_history()` entirely.** Its only reader, `telemetry_build_packet()`, worked around its own missing `a_mv`/`v_mv` parameters by re-reading "the most recently pushed history sample." Trace: `sensing_generate_sample()` (now `SensingService::sample()`) runs exactly once per tick, immediately before `pacer_core_handle_state()`'s telemetry calls, so the history-buffer read and the value already passed to `telemetry_log_event()`'s own `a_mv`/`v_mv` parameters were always identical. Confirmed equivalent, not assumed.
- **#13 — `update_refractory_windows()`'s dual-chamber and non-dual-chamber branches were byte-for-byte identical logic** (same condition, same body, in both arms of the legacy `if (mode_is_dual_chamber(...))`). Collapsed to one branch.
- **#17 — main.c's "re-scan the most recent log entry to tally events" removed.** Replaced with a direct read of each tick's own `StepOutcome.evt_flags` (now available because `PacingEngine::handle_state()` returns it directly, instead of requiring a second, independent re-derivation from the log).
- **Collapsed dead `PacerState` variants** (`ST_A_PACE`, `ST_V_PACE`, `ST_VRP`, `ST_PVARP`, `ST_ARP`, `ST_MODE_SWITCHED`). `grep`-confirmed: nothing in the legacy codebase ever assigns `g_state` to any of these six values — the state-switch's own handling of them (immediately reverting to `ST_WAIT_LRL`) was unreachable dead code, exactly as `pacer_core.c`'s own header comment already flagged ("a remnant of an earlier design that was never fully removed"). Not one of the 6 named findings, but the same "unreachable by construction" principle applies cleanly.
- **`PacerState::Fault` variant kept, deliberately unreachable.** Nothing in `PacingEngine`'s exhaustive match can produce it (the legacy state-switch's `default:` arm required an out-of-range `g_state` value, impossible for a closed Rust enum). Kept only so the CLI-level "if state==FAULT, abort" check — `test_main.sh`'s own pinned "KNOWN, CONFIRMED GAP" — stays structurally present for parity, per the same defensive-depth-vs-remove judgment call the architecture proposal flagged for findings #1/#2 (Section 6).

## Part C — Preserved quirks (deliberately NOT fixed — outside the approved 6 findings)

Preserving these exactly, even though several look like bugs, is a direct application of Rule 2 ("preserve behavior first... a faithful, slightly unidiomatic translation... beats an elegant rewrite that silently changes behavior") and Rule 3 ("do not invent business logic... where legacy logic is ambiguous, flag it, don't guess a reasonable interpretation"). None of these were in the approved findings list, so none were fixed:

- **#15 — The atrial-interval-always-computes-to-~1 quirk.** `pacer_core_tick()`'s own comment already documents this: `g_last_a_evt_ms` is set to `g_tick_ms` inside `handle_state()` on an atrial sense, so the interval recomputed immediately afterward in the caller is always `0` (forced to `1`). This means `ArrhythmiaService` always receives `interval_ms=1` on any atrial sense, classifying every single atrial sense as "fast" (`60000/1 >> 180`) regardless of actual physiological rate. **This is confirmed live in the migrated binary** — a smoke-test run showed AMS engaging after only ~7 seconds of simulated DDD pacing, consistent with 8 atrial senses (not 8 genuinely-fast intervals) triggering it. Fixing this would materially change arrhythmia-detection behavior for every dual-chamber mode — explicitly out of this stage's approved scope.
- **#3 — `mode_from_string()`'s silent VVI fallback for unknown mode strings**, preserved exactly (no new error path added).
- **Debounce window asymmetry** (`sensing_check_atrial`: >40ms; `sensing_check_ventricular`: >60ms) — an undocumented legacy copy/paste divergence, preserved as-is.
- **`~vrate` status-line computation's mismatch with `arrhythmia.c`'s own internal rate check** — both derive an implied rate from a v-interval using different integer rounding; preserved, not unified.
- **The dual-chamber `ST_WAIT_LRL` ventricular safety-net fallback** (`handle_wait_lrl_dual`'s final `if since_v >= lrl_ms+avi_ms`). Unlike the single-chamber fallback (Finding #2, proven dead for all 12 real modes), this one was **not** proven unreachable by the characterization suite — hand analysis suggests it is very narrowly reachable only under unusual parameter combinations, but was not dynamically confirmed dead the way Finding #2 was. Preserved as literal, reachable code rather than eliminated. **Flagged for human clarification:** if a future Verification pass proves this branch is also genuinely dead under all reachable parameter combinations, it becomes a candidate for the same "unreachable by construction" treatment as Finding #2 — but that determination should not be guessed here.

## Part D — Explicit ambiguities flagged for human clarification

1. **#8 — LCG/RNG seeding source.** Legacy seeds `sensing.c`'s and `battery.c`'s independent LCGs from `time(NULL)` internally, at `init()` time. The migrated `SensingService::new()` / `BatteryService::new()` take the seed as an explicit constructor parameter instead (a deliberate, disclosed architectural improvement — no hidden `time()` dependency inside a domain service). `SimulationOrchestrator::new_from_time()` reproduces the legacy default for normal CLI use. **#16 — however**, the orchestrator currently derives BOTH services' seeds from the SAME single caller-supplied seed, whereas legacy seeded them independently (`sensing`: raw `time(NULL)`; `battery`: `0x9E3779B9 ^ time(NULL)`). This is disclosed, not hidden, but is a genuine simplification a human should confirm is acceptable — a real air-gapped deployment with a hardware RNG would very likely want independent seeding restored.
2. **#12 — On-disk NVRAM byte order.** The legacy `NvramParams_t` was a raw `#pragma pack(push,1)` struct `fwrite()`'d directly, with no explicit byte-order handling — whatever the compiler's native layout was on the build/test platform (little-endian, in every characterization run this engagement performed). `PersistenceService` explicitly serializes little-endian to stay byte-compatible with files the legacy binary produced. **This needs re-verification against an actual `pacer_nvram.bin` file captured on the real air-gapped target**, not against source reading alone, if that target's architecture differs.
3. **Finding #1's deletion of `mode_step()`** — see Part A, row 1. Confirm no planned caller existed before treating this as permanent.
4. **The dual-chamber safety-net fallback** — see Part C's last bullet. Confirm whether it should be (a) left as reachable defensive code (current state), or (b) proven dead and eliminated in a future pass, once a dedicated reachability analysis (matching the rigor the original characterization suite applied to Finding #2) is run against it.
5. **`ams_active` in `main.c`'s legacy final-summary line** — the CLI's final summary now reports the true end-of-run `ArrhythmiaService::ams_active()` state (`SimulationReport.ams_active`), sourced correctly through the new architecture; flagged here only so a reviewer knows this field is real, not a placeholder (an earlier draft of this CLI briefly stubbed it to `0` before being corrected during the build-and-fix loop — see `BUILD_LOG.txt`'s test history).
