# eeprom.c Characterization Test Suite

Generated by the Verification & Test Agent stage of the AEGIS-derived
Legacy Modernization pipeline, as the unblocking step for `eeprom.c`'s
Phase-0 pilot candidacy (see Discovery + Risk & Triage report,
2026-09-20).

## What this is

A **characterization test suite**, not a spec-conformance suite. It pins
the *current, observed* behavior of the real, unmodified `eeprom.c` -
including behavior the source code's own comments flag as a smell (e.g.
`eeprom_load()` collapsing four distinct failure modes into one, and
silently persisting defaults back to disk on a missing-file load). That
is intentional: a refactor should have to break one of these assertions
*on purpose*, with a reviewed follow-up change to this file, rather than
silently drifting behavior.

It links the real `eeprom.c` against the real, unmodified rest of the
codebase (`pacer_core.c`, `modes.c`, `sensing.c`, `telemetry.c`,
`battery.c`, `arrhythmia.c`) rather than mocking any global state, so
nothing about struct layout, global storage, or constants is guessed.

No file outside `tests/` was created or modified to produce this suite.

## Results (last run, 2026-09-20)

- **54 / 54 assertions passing**
- **95.08% line coverage of `eeprom.c`** (122 lines), measured with `gcov`
  - exceeds the engagement's 85% test-coverage floor
- **Known, documented gap:** `eeprom_save()`'s I/O-failure branches
  (`fopen()` failure, partial `fwrite()` ×2) are not exercised - these
  require an unwritable-path / simulated-disk-failure setup that is
  platform/permission-dependent. Flagged rather than faked.

## Running it

The build file is named `tests.mk` rather than `Makefile` (kept out of
the top-level build's discovery path on purpose - this suite is
opt-in, not part of `make all` at the project root).

```
make -C tests -f tests.mk run         # build and run the suite
make -C tests -f tests.mk coverage    # build with gcov instrumentation, run, report %
make -C tests -f tests.mk clean       # remove build/coverage artifacts
```
